# Phase Plan

Act as a thin adapter over `$ar-feat-plan`:

1. Read the design supplied by the user and identify the next phase it describes.
2. Read prior phase reports only when they are clearly relevant to that next phase.
3. Turn the phase description and relevant prior results into the free-form introduction for `$ar-feat-plan`.
4. Read and apply `$ar-feat-plan` for exploration, interview, approval, plan contents, validation, and handoff.

Apply these phase-specific overrides:

- Scope the plan to the next phase rather than the entire design.
- Create the plan beside the design and name it consistently with that design and its existing phase artifacts.
